# H4 反例审查：沿用意图与未解配置

日期：2026-10-26。仅审阅冻结样本、实际请求/响应、本地代码与既有四仓报告；未调用模型或评审 API，未改提示、样本、评分或业务文件。本页是反例审查，不是修复验收。

## 可直接核对的事实

- [冻结 fixture](../../../examples/fixtures/memory_overlap_acceptance_v21.json) 的 H4 Source 只有“预发环境的限流参数继续沿用会议里那一版。”；H4-U1 事先要求：正文保留沿用意图、说明本条材料未给具体参数并待核对，唯一允许出口为 `needs_review`。同一 fixture 的总规则将路由定义为候选的**首要后续处理**，并禁止把未解所指仅因任务相关就归入 `task_constraint`。H5 则提供了同条可解析的具体回填规则，是防止机械处理“上述”的对照。
- [request-04.json](../../evidence/memw-overlap-v21-live-20261026-01/request-04.json) 证实实际 user payload 只有 `role/recorded_at/text`，系统提示明确“只根据这条原消息提取”；提示另写“缺少前文而无法解析执行所需的方案、步骤或配置时，应 needs_review；content 保留沿用意图和本次材料缺少所指细节”。三个示例没有 H4 原句或同类配置指代示例。
- 真实输出是“用户要求预发环境的限流参数继续沿用会议里的那一版。”，`task_constraint`；reason 为“明确的任务执行约束，指示沿用特定版本的参数，未涉及猜测或需核验的冲突。”它没有编造 QPS 或其他值，却没有说明**本条无法确定哪组参数**。这可从 Source 与输出直接观察；不能从一次输出断言模型内部为何漏掉。
- [semantic-review.json](../../evidence/memw-overlap-v21-live-20261026-01/semantic-review.json) 给 H4 正文和路由均失败；[acceptance.json](../../evidence/memw-overlap-v21-live-20261026-01/acceptance.json) 记录本轮技术 6/6、严格语义 6/7、整案 5/6、整体未通过，6 次额度已用完。[evidence-check.json](../../evidence/memw-overlap-v21-live-20261026-01/evidence-check.json) 记录实际 payload/数据快照匹配、gold 未入请求。该分数不可因事后重新解释 H4 而追溯改写。
- [EXTRACTION_PROMPT](../../../mini_pi/memory/extraction_client.py) 已有局部规则，但 [route_candidates](../../../mini_pi/memory/selection.py) 仅按建议标签归组，不识别未解参数；MEM-04 消费未实现。因此不能拿未来“消费层会拦住执行”当现有保障。`Source` 绑定证明候选来自哪条消息，不证明该消息中存在具体参数，也不证明当前任务归属。

## 对两个假设的挑战

**A. “H4 必然 `needs_review`，正文必写缺口。”** 对**本轮冻结的单 Source、单出口、首要后续处理契约**，是成立的：沿用意图已知；执行所需版本无法从唯一输入解析，下一步应定位会议配置。正文最好写“本条材料未给出具体限流参数/无法确定所指版本”，而不是“会议从未确定配置”。后一句超出 Source。冻结要求把缺口放在 `content`，只有 `reason` 或原 Source 能看出不够。

但这不是源文本本身强制的唯一分类。在另一种**事先定义**的契约里，`task_constraint` 可以只记录“用户要求沿用会议版”，并由独立状态标明“参数未解析、不得执行”。那需要新的字段或明确的消费门禁、版本化样本与后续测试。当前三字段/五出口及未实现的 MEM-04 不能证明这种替代方案已安全落地；事后把 H4 的 gold 放宽为两个出口，会改变冻结验收含义。

单 Source 可以证实“**本条没有**数值或可唯一定位的版本标识”，不能证实“会议不存在那版”“其他会话/纪要也找不到”或“用户意图不确定”。后续检索若找到受信的确切配置，可以生成经核对的新材料供任务执行；提取阶段不能把未来可能检索到的值冒充当前 Source 的内容。`needs_review` 应保留已知沿用意图及待查对象，不能使它在 MEM-04 静默消失。

**B. “加一个同类 few-shot 就能修好。”** 目前提示第 59 行已有一般规则；这一次真实响应仍漏掉缺口。增加一个不同措辞的示例可能改善模型表现，不能从一次失败推出充分性、稳定性或泛化。过近示例还可能只学到“那版→needs_review”，误判 H5 那类同条给出完整规则的情况。提示中的“缺少前文”可能使模型把会议外部材料排除在规则之外；这只是可检验的措辞假说，真实响应不能证明因果。更精确的概念是“本次提取输入能否确定执行所需对象”，而非有没有“前文”或某个指代词。

## 用来推翻过宽规则的反例

| Source 形态 | 最小判断；均为拟定反例，未运行模型 |
| --- | --- |
| “预发按会议里那版限流参数。”且本次输入无纪要、版本号或参数 | 保留沿用意图与本条未解缺口；依当前契约 `needs_review`。H4 即属此型。 |
| “会议版限流参数是 QPS 120、并发 20；预发继续沿用。” | 同条已有对象和值，可提取明确要求为 `task_constraint`；不因“会议版”一词待核对。数值只是构造反例，不是 H4 事实。 |
| “预发使用配置仓库中 `rate-limit.yaml` 的不可变提交 SHA `abc...`、profile `preprod`。” | 若标识确能唯一定位目标，抽取“使用该标识”的明确要求可为 `task_constraint`，即使本条未展开数值；执行前仍须读取、校验目标，不可假称模型已核验参数。若路径/SHA/Profile 不足以唯一定位，则仍需核对。 |
| “先查会议纪要第 3 节的参数，确认后再改预发限流。” | 已明确的“先查、确认后改”是条件式任务要求，可归 `task_constraint`；参数值仍不能猜。不能把所有待获取信息都机械改成 `needs_review`。 |
| “预发沿用会议里那版；本次变更还必须先备份现有配置。” | 未解限流版本与独立明确备份要求应拆开处理；不能用 H4 的缺口吞掉后者。 |

这些反例说明判定单位是**独立候选及其使用前提**。确切值未出现在单条文本，不总等于“要求含义不明”；能否唯一定位目标、当前候选是记录指令还是直接提供可执行参数，才决定是否需要先查。`task_constraint` 从不直接授予执行权限。

“精确指针”也要分清：不可变 SHA + profile 只是让**用户要求使用哪个对象**变明确，并未证明仓库、提交、配置内容确实存在或获审批。若用户断言“该提交已经批准/参数已核验”，这条**结果断言**缺外部依据时可以另作为 `needs_review`；若只是要求“使用该提交”，要求本身可为 `task_constraint`，运行前仍要读取、校验配置和权限。只有可变分支名 `main`、笼统文件路径或可复用的会议名称，可能无法固定“那一版”；但如果用户明确要求“使用执行时的最新 `main`”，这是另一种清楚的操作规则，其漂移风险应在执行门禁处理，不能仅因可变就把指令判错。H4 既没有具体参数，也没有足以检索和辨认目标的锚点，这才是本次冻结审查的实质缺口。

## 最小建议及验收边界

1. 保持本轮冻结 6/7、5/6 和 H4 双项失败。先把判定语句审成“**本次提取输入缺少执行目标的具体内容、可辨认引用或明确检索步骤**”与“**本次输入已有可解析步骤/值/引用，或明确先检索再执行**”的区分，且明确输出只能说本条缺什么。以此复核 H4、H5 和上表反例，避免关键词规则。此为人工契约澄清建议，尚未修改提示。
2. 若以后获准改提示，可考虑简短补充一对“未解所指 / 同条已解析所指”的对照，而不是只堆一个正例。示例、措辞都仅是待测方案，不声称会修复模型；现有规则已在却失败，不能把提示当程序门禁。
3. 未来新预算下，在提示和 gold **预先冻结**后，用独立措辞与“稳定指针但未列数值”等反例复验。分别报告正文保真、路由、完整语义及整案；不重算旧 S3 或本轮 6/7。MEM-04 另验：`needs_review` 保留沿用意图并触发待澄清呈现；`task_constraint` 中的稳定指针仍须解析和核验后才可执行。当前都未实现/验证。

四仓既有[源码报告](report.md)未提供 Mini-Pi 五出口同构优先级。以上结论以本地冻结契约、实际 H4 原文/响应和现行归组代码为证据；未来消费安全与改提示效果均属未验证推断。
