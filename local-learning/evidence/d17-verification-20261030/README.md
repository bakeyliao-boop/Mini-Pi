# D17 摘要流程模拟验证

验证日期：2026-10-30。使用合成会话、预设摘要和模拟回答；没有调用真实模型或执行实际文件修改。`auth.py` 和 `test_login` 均是测试例子。

## 一次成功流程

原始任务是“修复登录，不修改验收测试”，历史中记录“已修改 auth.py、test_login 失败、待检查数据库”。实际触发了摘要并写入摘要记录，随后回答模型收到：

```text
旧会话摘要：目标修复登录；不修改验收测试；已修改 auth.py；test_login 失败；待检查数据库。
近期消息：继续
```

原始三条历史完整保留，模拟回答随后追加。实际会话文件：[normal-session.jsonl](normal/normal-session.jsonl)；完整的原始历史、摘要输入、摘要记录和回答请求：[normal-evidence.json](normal/normal-evidence.json)。

## 失败和边界

- 模拟摘要截断、报错或中止：原始历史保留，不保存失败摘要，回答模型未调用。
- 摘要保存后加入 steering，使最终请求超过窗口：返回 `budget_exhausted`；已保存摘要、新消息和原始历史都保留，回答模型未调用。
- 回答轮数上限设为 1，本次实际发生摘要调用 1 次、回答调用 1 次；摘要有单独的 1 次上限，第二次摘要被阻止。总时限为 30 秒。

具体检查结果及每个场景的会话记录见 [failure-summary.md](failure/failure-summary.md) 和 [failure-results.json](failure/failure-results.json)。

## 请求大小与消耗口径

成功场景的回答输入估算为 37 tokens，加输出预留 1000 和安全余量 100，小于窗口 10000。37 是程序按字符估算的数值，不是服务端实际 token 使用量。

摘要和回答都是模拟响应，没有服务端 `usage`；记录为 `null`（不可用），不当作 0。`max_model_turns` 限制回答轮数，摘要调用由独立上限控制，两者共享总时限。
