# D17 失败、窗口与预算验证

本次使用预设响应的 `MockProvider` 和合成历史，在本目录写入独立会话记录；没有调用真实模型。所有结果来自实际运行 `run_failure_evidence.py` 的检查，不代表真实模型的摘要质量或服务端 token 使用情况。

| 场景 | 实际结果 |
| --- | --- |
| 摘要输出截断（length） | 运行返回 error；原始历史完整；没有保存摘要；回答模型调用 0 次。 |
| 摘要报错（error） | 运行返回 error；原始历史完整；没有保存摘要；回答模型调用 0 次。 |
| 摘要中止（aborted） | 运行返回 cancelled；原始历史完整；没有保存摘要；回答模型调用 0 次。 |
| 摘要保存后新 steering 使最终请求超过窗口 | 运行返回 budget_exhausted；原始历史与新消息保留；已生成的摘要仍保存；回答模型调用 0 次。 |
| 回答轮数上限为 1 | 正常结束；摘要模型调用 1 次、回答模型调用 1 次。该上限是回答轮数上限，而非模型调用总次数。 |
| 摘要单独上限为 1 | 第二次摘要请求被阻止；实际摘要模型调用仍为 1 次。 |

摘要、回答的实际 token `usage` 均不可用，机器结果写作 `null`，不表示零。测试中的窗口占用是程序估算值，不是服务端 token 数。

详细检查结果见 [failure-results.json](failure-results.json)，每个失败和窗口场景的实际会话记录见同目录 JSONL 文件。完整可复现代码见 [run_failure_evidence.py](run_failure_evidence.py)；重跑时先把脚本复制到新的空目录，并在 Mini-Pi 项目根目录下执行。脚本会拒绝覆盖已有证据；模块查找路径已调整为当前项目目录，适配其他设备。
