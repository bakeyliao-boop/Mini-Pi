# MEM-03 语义检索小样本评测计划

本计划接在两次真实API连通性验收之后。连通样例中的0.660/0.411只记录该问题的实际分数，不用于选择本轮阈值。本轮不修改MemoryStore.search、适用性过滤、排序、模型或向量缓存策略；评测与运行辅助由助手准备。

## 固定数据与范围

数据文件：`examples/fixtures/memory_embedding_eval_v1.json`，版本`mem03-semantic-v1`。全部为合成文本；各案使用独立的临时SQLite、可信用户/项目范围和相同有效时间。每案2或3条记忆，全部处于有效状态。身份、版本、撤回等既有确定性门禁另行保留，不用本轮语义样例替代。

| 案例 | 分组 | 检查目标 | 应返回的本案记忆ID |
| --- | --- | --- | --- |
| C1 | 校准 | 从同义问题找回Python示例偏好，排除部署脚本语言 | A |
| C2 | 校准 | 学习时段和提前提醒同时需要，不能只召回其中一条 | A、B |
| C3 | 校准 | 只有数据库学习记录时，水果偏好没有相关记忆 | 空 |
| H1 | 独立验收 | 理解流程的个人偏好，区分项目文档工具 | A |
| H2 | 独立验收 | 练习时间和设备两条必要证据完整召回 | A、B |
| H3 | 独立验收 | 编辑器使用记录不能提供宠物名字 | 空 |

自然query和保存原文可以发给embedding。分组、标准ID、评分说明仅在本地使用，不拼入问题或正文。本轮只评检索结果，不调用生成模型、不评最终回答或声称已接入Context。相似度不能证明事实或推导未明说的偏好；无相关信息案例只验检索空结果，合理拒答仍是后续实际回答链路的验收项。

## 校准与冻结

1. 固定`text-embedding-v4`、1024维、原生query/document模式和`top_k=2`。
2. 只对C1–C3各执行一次实际search，使用`min_score=-1`、`top_k=本案记忆数量`观察全部合法候选分数。
3. 在本地离线按现有`score >= threshold`及最终`[:2]`复演。阈值候选仅由这三案的分数分界生成；选择三案全通过的最宽可行分数区间中点，同宽选择较高阈值，端点-1/1作为零宽边界候选。
4. 没有一个共同阈值能通过全部校准案例，则报告校准失败、保留结果并停止，不消耗独立验收预算。技术故障单列，不能当作语义空结果。
5. 成功后冻结本轮阈值；再对H1–H3实际调用search，直接传入冻结的阈值和top_k=2。不得用H组结果回头调参、改标准或重跑直到通过。

校准阶段的阈值比较是离线复演，不伪称已逐个阈值重新调用在线search；独立验收阶段才是实际使用冻结参数的在线检索。本地分数留存只用于本轮评测，不引入生产向量缓存。

## 评分与结论

逐案列出实际返回ID、原文、来源、版本、相似度、遗漏ID和额外ID；返回ID集合恰好等于事先标准才记该案通过。单条正确不能掩盖多条证据漏召回；平均指标不能掩盖任何失败。未知案例中技术失败不能算空结果正确。

六案全通过也仅表示这组小型试点通过，不代表生产阈值稳定、泛化质量已证明或整个记忆系统完成。失败时先定位适用性过滤、相关性、阈值或限量环节，未经说明不增加重排、混合检索或其他算法。

## 调用与记录预算

每案最多一次query请求、一次document请求；每案正文≤3条，不触发多批。前三案最多6次，校准成功后后三案最多6次，整轮最多12次embedding请求、20条输入文本。发送层独立计数，创建第13次请求前停止；无自动重试。校准失败或技术异常提前停止，已发生用量仍如实记录。

记录每请求可得的token/request_id/耗时，分开记录临时记忆准备、search及总耗时。费用未核账保持未知。仅使用临时库，不读真实Session，不改既有记忆库、D13暂停现场或核心代码。
