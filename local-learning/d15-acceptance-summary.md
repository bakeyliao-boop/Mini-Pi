## ① 请求流程：先准备记忆，再交上下文构建器

Harness组装组件、Agent传递配置时不检索。每轮请求前，run_loop把原始history深拷贝交给prepare_messages；绑定的prepare_context检索记忆并调用记忆模块build_context，核验后把带来源的参考消息加入副本。准备结果交给ContextProvider，再交默认FullHistoryContext，最后交实际模型适配器。

原始history记录实际消息；注入的参考消息不直接写回。真实模型回复及工具结果照常追加；模型回复可能引用参考材料，因此撤回记忆不等于抹去历史影响。记忆模块build_context负责预组装，与ContextBuilder.build职责不同。

| 时点 | 原始history | 本次请求副本 |
| --- | --- | --- |
| 准备前 | 用户任务 | 尚未生成 |
| 记忆准备后 | 用户任务 | 参考材料＋用户任务（如有system则材料位于其后） |
| 模型调用工具并取得结果后 | 用户任务＋模型调用＋工具结果 | 上轮副本不机械写回；下轮从新history重建 |
| 未来压缩后 | 完整历史仍保留 | 参考材料＋摘要＋近期完整消息（示意，具体契约待D16/D17） |

## ② 配对与安全切点

ToolCall.id与ToolResult.tool_call_id配对，工具名称也须一致。_check_complete_recent以pending字典登记等待结果的调用，拒绝孤立/重复/错名/缺失结果及工具组被普通消息打断。一次assistant中的多调用及对应结果要整体保留或整体进入摘要区域；摘要文字不能替代结构化调用去配对保留结果。

Pi从合适user或assistant消息开始保留，不能从toolResult开始；可以在用户回合中途切分，并为切走的回合前缀准备摘要。保留近期大小是近似目标，不可为凑数拆散工具组。

回复length截断时，当前loop逐ID产生“未执行”错误反馈，执行器零调用；配对完整不代表执行成功。工具执行中取消/超时缺结果时只说明结果未知，不能补造“未修改”。pending写入先过恢复核对，不能靠压缩隐藏。

## ③ 字符预算与模型窗口

messages_char_count统计内部消息数据类转字典后JSON字符串的len，包含正文、调用、结果、材料及字段，不是字节数或token数。材料加入后大于max_context_chars则报错，恰好等于可通过。统计不包含单独tools和完整供应商消息模板；适配器还会转换消息及加入工具定义。

构建最终内容后，按目标模型规则检查完整输入、输出预留和必要余量。输入/输出各自上限与总窗口均须考虑；字符通过不保证token够，字符失败也不证明token超限。max_model_turns、total_timeout_seconds、max_completion_tokens各管轮数、时间、输出，不能代替累计token或费用预算。

当前Harness拒绝同时配置记忆准备与自定义context_builder，避免检查后再不透明扩张；未来放开须明确变换顺序及最终门禁。字符检查前检索可能已调用embedding，后续拒绝回答请求不代表零消耗。

## ④ 摘要事实与来源

| 必须保留 | 具体要求 |
| --- | --- |
| 目标 | 当前任务及成功判据 |
| 约束 | 最新有效权限、范围、禁止项；旧指令变化可回查 |
| 状态 | 实际操作、完成/未完成/未知；区分计划与执行 |
| 验证 | 哪次、何时、对哪个修改状态执行；不能把曾经通过写成当前通过 |
| 下一步 | 待办、阻塞及需要核实的事项 |
| 来源 | 路径、调用ID或会话位置，能支持对应结论；不能只附来源却扩大结论 |

例：可写“编辑工具报告修改完成，修改前测试失败，修改后尚未复测”；不能写“问题已修复，测试通过”。新代码修改后，旧通过结论要加时间/版本边界；后续用户收紧权限时更新当前约束，原历史不删除。假设、观察及未执行反馈不能升级成确认事实。

## ⑤ 失败、截断、取消与超时

当前prepare_messages普通错误归RequestPreparationError并结束error；取消和总时限分别保持cancelled/timeout，原始history保留。准备成功后还要再次检查取消/截止，才进入Provider；资源清理完成后才结束。普通builder/Provider异常不被同一个大范围except冒充为准备失败。

Pi拒绝error/length摘要及摘要中的工具调用；Mini-Pi摘要尚未接入。D17须保留原历史与已有有效摘要，候选摘要未通过不得替换有效上下文。失败后若明确允许回退，也只有完整上下文配对/空间合格、未取消/超时、预算允许时才可继续。不能向模型发送已知超限原文；超时后即使摘要完整也不启动下一回答请求。失败不撤销已经发生的消耗，协作取消/同步阻塞不承诺硬实时截止。

## 理解检查与证据边界

学习者在有提示、可看代码的条件下，确认了副本/历史边界、调用时点、整体工具组、未知副作用、字符/token区别、检索既有消耗、摘要最终组装后检查、历史状态更新以及超时禁止后续请求。过程曾将“传递配置”误认为检索时点、将“先检查再加入摘要”作为最终检查，经说明后已正确复述。

教学期间执行过请求准备/跨层整合定向测试18项、配对与字符边界专项、请求准备8项复测；这些只支持已有接线行为，不证明摘要实现或云端语义。此次归档为文档更新，未新增核心代码、云请求或全量回归。
