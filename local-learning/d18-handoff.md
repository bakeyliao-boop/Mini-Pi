# D18 工具执行前检查：学习起点

> **2026-11-02 进度：**`read_file`、`edit_file`、`list_files` 和 `run_tests` 四个默认工具的参数检查与实际执行已拆开，`ToolRouter.prepare_call` 可检查并准备这些工具；`execute_tool_with_rule` 已接入 `run_loop` 的可选 `before_tool_call`，`Harness` 新建与恢复入口经 `Agent` 转发规则。临时文件、受控测试进程和模拟模型验证：规则拒绝编辑时不写入、拒绝列目录时不扫描、拒绝运行测试时不启动进程，拒绝原因和调用编号进入模型请求；允许时正常执行，原有文件与目录范围、取消和时限检查仍生效。尚无内置默认禁止修改测试文件的规则；源码曾出现回退，原因未确认。

> **规则示例核对：**学习者编写的 `examples/d18_test_protection.py` 保护指定登录测试文件。首次联动测试发现 `Agent.prompt` 漏传规则，助手恢复这处转交；实际临时文件及模拟模型验证拒绝、允许和关闭规则，连同新建与恢复入口等相关检查共 22 项通过。回退原因未确认；示例规则不会默认启用。

> **拒绝记录：**规则拒绝统一由 `tool_hooks.py` 添加“执行前规则拒绝：”前缀；示例规则只返回具体原因。实际验证了该文字进入模型请求及会话记录，恢复后仍可与本例的工具执行失败文字区分。这是可读文字约定，不是独立、可靠的结构化错误类别。

> **接口与样本：**调用 `protect_login_test(workdir)` 创建规则，通过 `Harness(..., before_tool_call=rule)` 配置；规则收到参数已检查的 `ToolCall`，返回 `None` 允许或返回非空字符串说明拒绝。模拟模型与同一真实编辑工具的拒绝、允许记录分别保存在 `local-learning/evidence/d18-hook-demo-20261102/denied.jsonl` 与 `allowed.jsonl`；此目录被 Git 忽略，跨设备不会自动同步。未请求真实模型。

## 先看一个例子

假设某个测试文件在工具的基础允许范围内，但当前任务额外规定“不要修改验收测试”。模型提出修改该文件时，执行前规则应拒绝它：文件不发生写入，同时将拒绝原因作为与原调用对应的工具结果交给模型。

## Pi 源码与当前 Mini-Pi

- 固定学习基准为 `7f9e1198f2f7a8cf5ea18d5010ba081d4d60c333`。[固定源码](https://github.com/earendil-works/pi/blob/7f9e1198f2f7a8cf5ea18d5010ba081d4d60c333/packages/agent/src/agent-loop.ts#L708)先找到工具并校验参数，再调用 `beforeToolCall`；拒绝时不执行工具，返回带原因的错误结果。
- 2026-10-30 实际核对的上游 `main` 为 `4b535d57ea8863dbba44b89872146523da271786`；[该版本的对应代码](https://github.com/earendil-works/pi/blob/4b535d57ea8863dbba44b89872146523da271786/packages/agent/src/agent-loop.ts#L669)在上述核心顺序上相同。此处只比较了本章相关代码，不表示两版本全部行为一致。
- Mini-Pi 当前可在参数检查后执行可替换的规则，再决定是否调用工具；原有工具的路径等检查仍然生效。
- Pi 还支持扩展处理器修改输入等能力；Mini-Pi 当前只支持允许或拒绝，是明确的范围差异。
